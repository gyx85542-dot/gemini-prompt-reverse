# Gemini 提示词反推工具 — 设计说明

日期：2026-08-15  
状态：待用户审阅后进入实现计划

## 1. 要解决什么问题

本机单人使用的 Web 工具：把图片和/或文字交给大模型，配合可管理的系统提示词，产出一段「反推」文本（通常是可再用于生图的提示词）。产物就是模型原文，不做结构化拆栏。

每次开跑都必须落库。改系统提示词再跑 = 新卡片，旧卡片保留，新卡记下来源。历史以卡片墙展示，可搜索。

## 2. 已确认的约束

- 只在本机用，浏览器打开本地页面；不做账号、不做多端同步。
- 模型调用走 APIMart OpenAI 兼容接口，不直连 Google，浏览器不直连 APIMart。
- 反推结果 = 模型按「输入 + 系统提示词」生成的原文。
- 图、文都可选，但开跑时至少有一样。
- 系统提示词支持用户自建预设（新建 / 改名 / 编辑 / 删除），用时点选，仍可当场改再跑。
- 每张卡自选模型；默认 `gemini-3.5-flash`。
- 第一版不删除卡片；不按卡片单独拉角缩放。

## 3. 架构

一个本机进程同时提供页面和接口，默认 `http://localhost:8787`。

```
浏览器  →  本机服务（页面 + API）  →  APIMart
                ↓
         SQLite + 图片文件
```

- 前端：Vite + React 单页。卡片墙是唯一主界面。
- 后端：Node（Express 或同等薄框架）。只做三件事：读写 SQLite、存/读图片、把聊天请求转给 APIMart（含流式）。
- 密钥：`APIMART_API_KEY` 只放本机 `.env`，接口不返回给前端。可选 `APIMART_BASE_URL`，默认 `https://api.apimart.ai/v1`。
- 数据目录：`data/app.db`、`data/uploads/<cardId>/`。
- 卡片尺寸偏好：存在浏览器 `localStorage`，不是业务数据。

### 3.1 调用 APIMart 的方式

`POST {APIMART_BASE_URL}/chat/completions`

- Header：`Authorization: Bearer <APIMART_API_KEY>`
- `model`：卡片上选中的模型名
- `stream: true`
- `messages`：
  - 若系统提示词非空：`{ role: "system", content: "<系统提示词>" }`
  - `{ role: "user", content: [ { type: "text", text }, { type: "image_url", image_url: { url: "data:<mime>;base64,..." } }, ... ] }`
- 无文字时，user 的 text 用固定占位：`请根据图片进行反推。`（避免部分模型拒收空 content）
- 无图片时，user content 仅为文本。
- 系统提示词为空时不发 system 消息，只发 user。

前端永远看不到 API Key。图片由后端读文件后转成 data URL 再发给 APIMart。

## 4. 界面与操作

### 4.1 卡片墙

首页是平铺卡片，新的在前。

顶部：

- 「新建反推」
- 搜索框：对用户文字、系统提示词、产出做不区分大小写的包含匹配
- 卡片大小滑杆（小 / 中 / 大，或连续缩放）：所有卡片一起变；缩略图数量/尺寸、提示词与产出行数按尺寸截断

每张卡片必须能看出：

- 用了哪些图（缩略图；过大时只显示前几张 + 余数）
- 用了哪段系统提示词（按卡片宽度截断）
- 若有用户文字，再露一行
- 模型名（缩略时可用短名，如 `3.5-flash`）
- 时间、状态（进行中 / 成功 / 失败）
- 若是再跑来的：`来自 #id`，点击滚到并高亮源卡片

### 4.2 新建与开跑

点「新建反推」出现一张可编辑草稿卡（只在当前页面，未开跑不写库）。草稿上可：

- 添加 / 删除多张图（拖入或选择）
- 写用户文字
- 下拉选预设，选完仍可改系统提示词全文
- 选模型
- 点「开始反推」

开跑条件：至少有一张图或一段非空文字。否则按钮不可用，并提示原因。

第一次开跑时写入数据库，状态为进行中，产出区流式显示。成功或失败都更新同一张卡。刷新后草稿未开跑的会消失。

### 4.3 查看与再跑

点已保存的卡打开放大层（遮罩）：看原图、完整系统提示词、用户文字、完整产出、模型、时间、错误信息（若失败）。

- 失败：可改输入后在**同一张卡**重试。
- 成功：输入只读。提供「用新系统提示词再跑」：图和用户文字原样带到新草稿卡，系统提示词和模型可改（模型默认带原值）。新卡开跑后成为新记录，`source_card_id` 指向旧卡。旧卡不动。

### 4.4 预设

独立管理面板（弹窗即可）：名称 + 全文。名称必填且不可与其他预设重名。删除预设不改已保存卡片里的系统提示词原文；卡片上的预设 id/名仅供展示，缺了就只显示当时全文。

### 4.5 模型选择

每张卡一个下拉，默认 `gemini-3.5-flash`。

固定选项（按此顺序）：

1. `gemini-3.5-flash`（默认）
2. `gemini-2.5-flash`
3. `gemini-2.5-pro`
4. `gemini-2.5-flash-lite`
5. `gemini-3-flash-preview`
6. `gemini-3-pro-preview`

另有「自定义」：自由填写 APIMart 模型名，原样发送并随卡保存。

## 5. 数据

### 5.1 表 `presets`

| 字段 | 含义 |
|---|---|
| id | 主键 |
| name | 名称，唯一，非空 |
| body | 系统提示词全文 |
| updated_at | 更新时间 |

### 5.2 表 `cards`

| 字段 | 含义 |
|---|---|
| id | 主键 |
| created_at | 创建时间（第一次开跑时） |
| user_text | 用户文字，可空 |
| system_prompt | 当时实际发送的系统提示词全文，可空 |
| preset_id | 可空 |
| preset_name | 开跑时的预设名快照，可空 |
| model | 模型名，默认 `gemini-3.5-flash` |
| output | 模型产出全文，进行中时可部分写入 |
| error | 失败原因，成功时为空 |
| source_card_id | 再跑来源，否则空 |
| status | `running` / `succeeded` / `failed` |

### 5.3 表 `card_images`

| 字段 | 含义 |
|---|---|
| id | 主键 |
| card_id | 所属卡片 |
| file_path | 相对 `data/uploads/` 的路径 |
| original_name | 原始文件名 |
| mime | `image/jpeg` / `image/png` / `image/webp` / `image/gif` |
| sort_order | 展示顺序 |

图片只接受 jpg / png / webp / gif。单张超过 10MB 拒绝，并在卡片上说明上限。

## 6. 失败与边界

- 图文都空：不能开跑。
- 未配置 `APIMART_API_KEY`、APIMart 4xx/5xx、超时、流中断：卡片 `failed`，`error` 写清原因，可在同一张卡重试。
- 重试覆盖该卡的 `output` / `error` / `status` / 当时的系统提示词与模型；不新建卡。
- 搜索只过滤，不改数据。
- 第一版不提供删除卡片。
- 不校验自定义模型名是否存在；上游报错按失败处理。

## 7. 明确不做（第一版）

- 账号、权限、多端同步
- 对产出做主体/风格/相机词等拆栏
- 每张卡单独拖拽缩放
- 浏览器直连 APIMart
- 删除卡片
- 从 APIMart 动态拉模型列表

## 8. 验收

本机启动后打开工作台，以下均需成立：

1. 新建卡，只发文字或只发图，都能跑完并落库；刷新后卡片仍在，图、提示词、模型、产出一致。
2. 图文都空时不能开跑，有明确提示。
3. 能新建 / 改名 / 编辑 / 删除预设；选预设后仍可改文案再跑；删预设后旧卡提示词原文不变。
4. 搜索能按用户输入、系统提示词、产出过滤卡片。
5. 「用新系统提示词再跑」新增一张卡，旧卡不动，新卡有来源标记且图/文与旧卡相同。
6. 调卡片大小后，缩略图和提示词随尺寸截断，不要求看全。
7. Key 缺失或接口失败时卡片标失败并显示原因，同一张卡可重试。
8. 默认模型为 `gemini-3.5-flash`；换成列表中其他模型或自定义名后，该选择保存在卡上且实际请求使用该名。

## 9. 技术选型（实现时遵守）

- 前端：Vite + React
- 后端：Node，一个进程托管静态页与 API
- 数据库：SQLite（`better-sqlite3` 或同等同步库）
- 样式：足够看清卡片即可，不为视觉体系单独加依赖
- 仓库根目录即本工具；`.env` 不入库
